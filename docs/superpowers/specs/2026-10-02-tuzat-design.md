# Tuzat — дизайн

Дата: 2026-10-02
Статус: одобрен для написания плана

## 1. Цель

Tuzat — программа для Windows. Она исправляет текст, набранный не в той раскладке. Работает только вручную, по горячей клавише. Программа для личного использования, но код должен быть уровня продакшн: тесты, понятная архитектура, установщик.

**Критерий успеха:** пользователь набрал `ghbdtn`, нажал Pause и получил `привет`. Раскладка активного окна переключилась на русскую.

## 2. Объём

**Входит:**
- Исправление последнего слова по горячей клавише (по умолчанию `Pause`).
- Исправление выделенного текста по горячей клавише (по умолчанию `Shift+Pause`).
- Повторное нажатие `Pause` возвращает слово обратно.
- Пара раскладок в настройках. По умолчанию EN (`00000409`) ↔ RU (`00000419`). Поддерживается любая пара установленных раскладок, например TG ↔ EN.
- Иконка в трее с меню.
- Автозапуск через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- Unit-тесты для логики.
- Установщик Inno Setup для одного пользователя.

**Не входит:**
- Автоматическое определение и исправление раскладки.
- Словари и проверка орфографии.
- Логирование событий (есть только `crash.log` для необработанных исключений).
- CI.
- Авто-обновление, телеметрия, любые сетевые запросы.
- Поддержка окон, запущенных от администратора.
- Подпись кода (code signing).
- Сборки для arm64 и x86.

## 3. Платформа

- Windows 10/11, x64.
- .NET 10 (LTS), C#, WinForms.
- Publish: self-contained, `PublishSingleFile`, `EnableCompressionInSingleFile`. Без trimming: WinForms его официально не поддерживает.

## 4. Структура решения

```
Tuzat.slnx                     формат решения по умолчанию в SDK 10
Directory.Build.props          общая версия, Nullable, TreatWarningsAsErrors
build.ps1                      тесты → publish → iscc
README.md                      установка, настройки, ограничения, чек-лист ручной проверки
src/Tuzat.Core/                net10.0, без Win32 и WinForms
src/Tuzat.App/                 net10.0-windows, WinForms, WinExe
tests/Tuzat.Core.Tests/        xUnit
installer/Tuzat.iss            Inno Setup 6
```

**Главное правило:** вся логика, которую можно проверить без Windows API, лежит в `Tuzat.Core`. `Tuzat.App` — тонкий слой: он только вызывает Win32 и передаёт данные в Core.

## 5. Компоненты

### 5.1 Tuzat.Core

| Компонент | Ответственность |
|---|---|
| `VirtualKey` | Константы кодов клавиш Win32. |
| `KeyStroke` | `record struct`: `VirtualKey`, `ScanCode`, `IsExtended`, `Shift`. Одно нажатие для повтора. По `VirtualKey` определяется тип клавиши. |
| `KeyKind` | enum: `Printable`, `Space`, `Backspace`, `Reset`, `Modifier`, `Ignore`. |
| `KeyClassifier` | Чистая функция: код клавиши (VK) → `KeyKind`. |
| `WordBuffer` | Хранит нажатия текущего слова и применяет правила из раздела 6. Не потокобезопасный: его использует только поток хука. |
| `LayoutMap` | Двусторонняя таблица символов для пары раскладок A ↔ B. Создаётся из списка пар `(charA, charB)`. |
| `TextConverter` | Определяет направление и меняет символы текста по `LayoutMap`. |
| `Hotkey` | `record`: модификаторы (Ctrl, Alt, Shift, Win) + код клавиши. |
| `HotkeyParser` | Строка → `Hotkey` (`"Shift+Pause"`). Таблица имён клавиш хранится в Core. |
| `HotkeyBindings` | Пара хоткеев. По коду клавиши и модификаторам возвращает действие. |
| `HotkeyFilter` | Логика хоткеев из хука: срабатывание один раз за нажатие, «съедание» автоповтора и key-up. |
| `TuzatSettings` | Модель настроек, значения по умолчанию, проверка. |
| `SettingsLoader` | Чтение и запись JSON (`System.Text.Json`). Возвращает настройки и список ошибок. |

### 5.2 Tuzat.App

| Компонент | Ответственность |
|---|---|
| `Native/` | Объявления P/Invoke (`LibraryImport`): хуки, `SendInput`, HKL, `ToUnicodeEx`, буфер обмена. |
| `InputHooks` | `WH_KEYBOARD_LL` и `WH_MOUSE_LL` на отдельном потоке с циклом сообщений. Пропускает только свои события (метка `dwExtraInfo = 0x545A5401`). Ловит хоткеи через `HotkeyFilter`, работу ставит в очередь UI-потока. Нажатие кнопки мыши очищает `WordBuffer`. Поток отдельный: UI-поток часто ждёт, а Windows снимает хук, если его поток занят. |
| `ThreadWait` | Ожидание в UI-потоке, которое обрабатывает sent messages. Иначе чужой Ctrl+C зависает, пока Tuzat — владелец буфера обмена. |
| `FocusTracker` | Находит окно с фокусом и его поток через `GetForegroundWindow` + `GetGUIThreadInfo`. |
| `LayoutSwitcher` | Текущая раскладка потока с фокусом. Переключение через `WM_INPUTLANGCHANGEREQUEST`. Ожидание реальной смены раскладки. |
| `LayoutMapBuilder` | Строит `LayoutMap` из двух HKL через `ToUnicodeEx` с флагом `0x4`. |
| `InputSender` | `SendInput`: отпускание модификаторов, Backspace, повтор `KeyStroke` по скан-коду, Ctrl+C и Ctrl+V. |
| `ClipboardGuard` | Сохраняет и восстанавливает буфер обмена. Повторяет попытку, если буфер занят. Пишет текст, который не попадает в историю. |
| `FixLastWordAction` | Сценарий 7.1. |
| `FixSelectionAction` | Сценарий 7.2. |
| `Autostart` | Читает и пишет значение `Tuzat` в ключе HKCU Run. |
| `TrayApp` | `ApplicationContext` с `NotifyIcon`. Меню и уведомления. |
| `Program` | Mutex одного экземпляра, обработчики исключений, запуск. |

## 6. Правила `WordBuffer`

1. `Printable`: если последнее нажатие в буфере — пробел, буфер сначала очищается. Потом нажатие добавляется.
2. `Space`: нажатие добавляется. Пробелы после слова повторяются вместе со словом.
3. `Backspace`: удаляется последнее нажатие. Пустой буфер не меняется.
4. `Reset`: буфер очищается. Это Enter, Tab, Esc, стрелки, Home, End, PgUp, PgDn, Insert, Delete, F1–F24.
5. Любая клавиша, нажатая вместе с Ctrl, Alt или Win, очищает буфер.
6. `Modifier` (Shift, Ctrl, Alt, Win, CapsLock): буфер не меняется. Состояние Shift записывается в `KeyStroke`.
7. Окно с фокусом отличается от окна, в котором начался буфер: буфер очищается перед обработкой нажатия.
8. Если после добавления в буфере больше 64 нажатий, буфер очищается.
9. Клик мышью очищает буфер.
10. После исправления буфер **не очищается**. Повторное нажатие хоткея возвращает слово обратно.
11. CapsLock не записывается. При повторе он в том же состоянии, поэтому регистр сохраняется.

## 7. Сценарии

### 7.1 Исправить последнее слово (`Pause`)

1. Поток хука видит хоткей, «съедает» его key-down и key-up и копирует нажатия из буфера. Задача уходит в UI-поток.
2. `InputSender` отпускает все зажатые модификаторы: отправляет injected key-up для клавиш, у которых `GetAsyncKeyState` показывает нажатие.
3. Если копия буфера пуста, программа переключает раскладку и заканчивает работу.
4. Отправляет N нажатий Backspace, где N — количество нажатий в копии.
5. Переключает раскладку окна с фокусом на целевую.
6. Ждёт, пока `GetKeyboardLayout` потока с фокусом вернёт целевую раскладку. Проверка каждые 10 мс, не дольше 200 мс. После 200 мс программа продолжает работу.
7. Повторяет нажатия через `SendInput` с `KEYEVENTF_SCANCODE`. Для нажатий с Shift отправляет Shift-down и Shift-up вокруг клавиши.

### 7.2 Исправить выделенный текст (`Shift+Pause`)

1. Отпускает модификаторы, как в шаге 7.1.2.
2. `ClipboardGuard` сохраняет все форматы буфера обмена, которые можно прочитать. Форматы, которые вызывают ошибку при чтении, пропускаются.
3. Запоминает `GetClipboardSequenceNumber` и отправляет Ctrl+C.
4. Ждёт, пока номер изменится, не дольше 300 мс. Если номер не изменился или в буфере нет текста, программа восстанавливает буфер обмена и заканчивает работу.
5. `TextConverter` определяет направление (раздел 8) и меняет символы.
6. Кладёт результат в буфер обмена вместе с форматами `ExcludeClipboardContentFromMonitorProcessing` и `CanIncludeInClipboardHistory` (DWORD `0`).
7. Отправляет Ctrl+V.
8. Ждёт `clipboardRestoreDelayMs` и восстанавливает сохранённый буфер обмена.
9. Переключает раскладку окна с фокусом на целевую раскладку из шага 5.

### 7.3 Целевая раскладка

- Текущая раскладка — A: цель B.
- Текущая раскладка — B: цель A.
- Текущая раскладка не входит в пару: цель A.

## 8. `LayoutMap` и `TextConverter`

**Построение (`LayoutMapBuilder`):**
- Скан-коды: ряд цифр, три ряда букв, клавиша OEM_102. Для каждого скан-кода два состояния: без Shift и с Shift.
- Для каждой раскладки вызывается `ToUnicodeEx` с флагом `0x4`. Этот флаг не меняет состояние клавиатуры ядра и dead keys.
- Пара пропускается, если результат не равен ровно одному символу (мёртвая клавиша, нет символа, несколько символов).
- Пара пропускается, если символы одинаковые (цифры и т. п.).
- Если один символ попадает в две разные пары, остаётся первая пара. Так таблица остаётся однозначной.

**Направление (`TextConverter`):**
- Для каждого символа текста проверяется, есть ли он на стороне A и на стороне B.
- Символы, которые есть на обеих сторонах или ни на одной, не учитываются.
- Если символов стороны A больше, направление A → B. Если символов стороны B больше, направление B → A.
- Если символов поровну (включая 0), источником считается текущая раскладка.

**Замена:** каждый символ, который есть на стороне-источнике, меняется на парный. Остальные символы (цифры, пробелы, emoji, переводы строк) не меняются.

## 9. Настройки

Файл: `%AppData%\Tuzat\settings.json`.

```json
{
  "fixLastWord": "Pause",
  "fixSelection": "Shift+Pause",
  "layouts": ["00000409", "00000419"],
  "clipboardRestoreDelayMs": 200
}
```

| Поле | Проверка |
|---|---|
| `fixLastWord`, `fixSelection` | Парсится `HotkeyParser`. Клавиша — не модификатор. Два хоткея не совпадают. Буква, цифра или пробел — только вместе с Ctrl, Alt или Win. `Ctrl+Pause` запрещён: Windows выдаёт для него `VK_CANCEL`. |
| `layouts` | Ровно 2 значения, 8 шестнадцатеричных цифр (KLID), разные. Обе раскладки установлены (проверка в App через `GetKeyboardLayoutList`). |
| `clipboardRestoreDelayMs` | Целое число от 50 до 2000. |

**Поведение:**
- Если файла нет, программа создаёт его со значениями по умолчанию.
- Если JSON неверный, программа берёт значения по умолчанию для всех полей и показывает уведомление в трее. Файл не перезаписывается.
- Если неверно только одно поле, для этого поля берётся значение по умолчанию. Программа показывает уведомление с именем поля.
- Если хоткеи совпадают, оба хоткея получают значения по умолчанию.
- Пункт меню «Перечитать настройки» загружает файл заново, ставит хоткеи и заново строит `LayoutMap`.

## 10. Трей

Меню:
- **Пауза** (флажок). Пока пауза включена, хук пропускает все события, а буфер пуст. Состояние не сохраняется между запусками.
- **Автозапуск** (флажок). Показывает и меняет значение в HKCU Run.
- **Открыть настройки**. Открывает `settings.json` в Блокноте.
- **Перечитать настройки.**
- **Выход.**

Подсказка иконки: `Tuzat` или `Tuzat — пауза`.

## 11. Ошибки

| Ситуация | Поведение |
|---|---|
| Хук не установился | Сообщение с кодом ошибки Win32 и выход. |
| Windows сняла хук | Callback хука только читает данные и ставит задачу в очередь. На событиях `SystemEvents.PowerModeChanged` (Resume) и `SystemEvents.SessionSwitch` (SessionUnlock) хуки ставятся заново. |
| Буфер обмена занят | 5 попыток через 20 мс. Потом сценарий отменяется, а буфер обмена восстанавливается, если его уже меняли. |
| Раскладки из настроек нет в системе | Уведомление в трее. Хоткеи отключены, пока настройки не исправлены и не перечитаны. |
| Второй экземпляр | Mutex `Tuzat.SingleInstance`. Второй процесс сразу выходит. |
| Необработанное исключение | `Application.ThreadException` и `AppDomain.UnhandledException` пишут время, тип и stack trace в `%LocalAppData%\Tuzat\crash.log`. Потом сообщение и выход. |

## 12. Приватность

- Нажатия хранятся только в памяти, не больше 64 штук.
- Набранный и исправленный текст никогда не пишется на диск, в `crash.log` и в уведомления.
- Нет сетевых запросов.
- Временный текст в буфере обмена не попадает в историю Win+V и в менеджеры буфера обмена.

## 13. Известные ограничения

Эти пункты будут в README:
- Окна, запущенные от администратора, не поддерживаются (UIPI).
- В некоторых терминалах и играх переключение раскладки может работать неточно.
- Shift+Pause отправляет Ctrl+C. В терминале без выделения это прерывает команду. В VS Code без выделения копируется вся строка.
- Shift+Pause вставляет простой текст, форматирование теряется.
- Поля пароля нельзя надёжно определить. Нажатия в них тоже попадают в буфер (только в памяти).
- Неподписанный exe с хуком клавиатуры может вызвать предупреждение антивируса или EDR.
- Форматы буфера обмена с отложенной отрисовкой (delayed rendering) могут не восстановиться.
- Если приложение вставляет текст медленнее, чем `clipboardRestoreDelayMs`, может вставиться старое содержимое буфера обмена. Тогда значение нужно увеличить.

## 14. Тесты

xUnit, проект `tests/Tuzat.Core.Tests`. Тестируется только `Tuzat.Core`.

| Компонент | Случаи |
|---|---|
| `KeyClassifier` | Каждый `KeyKind` хотя бы на одной клавише. Буквы, цифры, OEM, пробел, Backspace, клавиши сброса, модификаторы. |
| `WordBuffer` | Каждое правило из раздела 6, включая переполнение, смену окна и пустой Backspace. |

| `TextConverter` | `ghbdtn` → `привет`; `руддщ` → `hello`; `Ghbdtn` → `Привет`; символы вне таблицы не меняются; смешанный текст; пустая строка; ничья → текущая раскладка. |
| `HotkeyParser` | `Pause`, `Shift+Pause`, `Ctrl+Alt+F12`, регистр не важен, пробелы вокруг `+`; ошибки: пустая строка, неизвестная клавиша, только модификатор, повтор модификатора. |
| `TuzatSettings`, `SettingsLoader` | Значения по умолчанию, неверный JSON, одно неверное поле, одинаковые хоткеи, неверный KLID, задержка вне диапазона. |

Для `TextConverter` и `LayoutMap` используется тестовая таблица EN ↔ RU, записанная в коде теста.

**Ручная проверка** (чек-лист в README): Блокнот, браузер (поле textarea), VS Code, Word, Windows Terminal, Telegram Desktop, окно от администратора (ожидается: ничего не происходит), повторное нажатие Pause, пустой буфер, выделенный текст из нескольких строк, восстановление картинки в буфере обмена.

## 15. Сборка и установщик

**`build.ps1`:**
1. `dotnet test`.
2. `dotnet publish src/Tuzat.App -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/publish`.
3. `iscc installer/Tuzat.iss /DAppVersion=<версия из Directory.Build.props>`.
4. Если `iscc` не найден, скрипт выводит команду установки `winget install JRSoftware.InnoSetup` и завершается с ошибкой.

**`installer/Tuzat.iss`:**
- `PrivilegesRequired=lowest`, `DefaultDirName={localappdata}\Programs\Tuzat`.
- `AppMutex=Tuzat.SingleInstance`.
- Ярлык в меню «Пуск».
- Задача (task) «Запускать при входе в Windows». Пишет значение `Tuzat` в HKCU Run (тот же ключ, что и в трее). Флаг `uninsdeletevalue`.
- Запуск программы после установки (по желанию).
- Деинсталлятор удаляет значение автозапуска. `%AppData%\Tuzat` остаётся.
- Результат: `artifacts/Tuzat-Setup-<версия>.exe`.
